# V10.18.4 Runtime Governance

Current execution version: **10.18.4**. The canonical runtime file remains under `CANONICAL_RUNTIME_V10.18.0/` for backward-compatible path stability; its internal runtime version is 10.18.4.

## New invariant
`weapon_execution_variant_integrity`: a remote weapon event must use a distinct execution variant after final A→B/B→C replanning. The variant must remove hand/weapon coupling after release, preserve weapon identity/mass/inertia, preserve causal trajectory, and never create a new Event.

## Output compatibility
The top-level Universal / Seedance 2.5 / MiniMax H3 output structures remain unchanged.


## V10.18.4 Semantic Variant Governance
- The final selected action is committed only after transition validation and B→C lookahead.
- Universal Weapon Control and the Execution Variant resolver run on that final action.
- For remote execution, `prompt_semantics.core_sentence` is the variant-authoritative sentence; native hand-held wording is retained only as `native_core_sentence` provenance.
- No new Event, Beat, Shot, weapon identity, or model output template is created by this repair.

## V10.18.4 Single-Source Compiler Governance
- SHOT_IR action_chain carries the committed `prompt_semantics` payload from the final Execution Variant.
- Native Compiler consumes that payload as the authoritative variant semantic core.
- Action Components may supply complementary outcome/recovery wording, but may not reconstruct or override remote-execution semantics.
- Deep QA verifies `prompt_semantics.core_sentence → SHOT_IR → semantic_trace → final prompt` end to end.
