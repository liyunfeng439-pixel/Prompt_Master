# Semantic Compression Compiler — 6.4

Compile meaning, not repeated prose.

Priority: `MUST > SHOULD > OPTIONAL`

## Safe compression
1. Deduplicate repeated facts.
2. Merge synonymous modifiers into one canonical phrase.
3. Preserve causal relations, event identifiers and temporal ordering.
4. Never compress identity locks, state transitions, action timing, spatial relations, force/contact logic, physical consequences or explicit user constraints.
5. Never collapse a multi-node causal chain into a decorative summary when that chain controls observable video behavior.
6. If limits are exceeded, remove OPTIONAL first, then compress SHOULD. If MUST cannot fit, escalate instead of deleting causal content.

## Compiler boundary
The compiled prompt is an output representation, not a source of truth. It may never mutate MASTER_COMBAT_STATE or IMMUTABLE_CANON.

### Protected causal chain
`PREP → MOTION → CONTACT → FORCE_TRANSFER → RESPONSE → ENVIRONMENT_RESULT`

Equivalent prose may be shortened; causal nodes may not be deleted or reordered.

## V6.9 Action readability compression
- Do not compress away the visible attack line, contact relation or force result.
- Replace internal terms such as `stylish_action_priority`, `heat_score`, `readability_score`, `complexity_change_count` with observable visual language or remove them entirely from the final prompt.
- When a Beat has been auto-split, retain the causal sequence while allowing each sub-beat to become a short executable clause.
- Prefer one strong verb + one contact/result phrase over multiple decorative synonyms.
