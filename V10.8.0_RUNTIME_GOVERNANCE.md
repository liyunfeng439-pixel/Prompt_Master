# V10.8.0 Runtime Governance

V10.8.0 is the single current corrective runtime.

Authority:
`SKILL.md → CANONICAL_RUNTIME_V10.8.0 → Combat Director V5.0 + Highlight/Impact Payoff / Spatial Combat Director V2.2 / Transition Graph V2.1 → SHOT_IR V10.8.0 → Native Output Router V10.8.0 → Deep Semantic QA → Regression Gate`

Zero-Copy remains the execution mode. Knowledge data is queried/referenced in process and is not copied into a parallel runtime database.

The runtime is generic: actor, weapon, ability, ending mode, scene, tactical state, spatial state, and environment anchors come from the scenario/asset Canon. No test character pair or fixed winner is part of compiler authority.

Spatial Combat Director V2.0 is current authority for 3D combat-space state. It maintains independent actor states, pairwise relative state, and known environment anchors. It never invents missing spatial facts and never overrides user constraints or Canon.


## Highlight / Impact Payoff Authority
Combat Director V5.0 may select high-value existing action knowledge using an impact payoff score. The score never invents an action, body detail, damage fact, secondary collision, environment anchor, or ability. Highlight events are carried into Event → Beat → Shot → SHOT_IR → native compiler as immutable semantic metadata.

The visual payoff chain is: tactical opening → action mechanism → contact geometry → force transfer → body/material response → displacement/result → authorized environment response → motivated camera emphasis → next tactical state.


### V10.7 Highlight Choreography Contract
- Highlight tier is calibrated; knowledge-schema completeness alone cannot produce Signature.
- Signature requires multiple independent payoff amplifiers plus visible displacement or environment payoff.
- Every highlighted Event carries a choreography profile: trigger → entry → contact → force transfer → body response → displacement → environment payoff → camera payoff.
- The profile may only reference facts already present in Canon/action knowledge.


### V10.7 Spatial Snapshot Integrity
- Every action Event stores immutable spatial before/after snapshots.
- The next action Event must inherit the previous action Event after-state actor layers without unexplained layer jumps.
- Horizontal reposition resolves a known anchor when available; otherwise it remains explicitly pending rather than inventing a location.


# V10.8.0 Closed-Loop Governance

1. 30s hard limit remains ≤7 Beats; Shot count is not hard-capped at 7.
2. Beat contains one causal combat unit; Shot boundaries are semantic camera boundaries.
3. Budget pressure cannot delete a unique causal result, but must affect Beat/Shot grouping and presentation density.
4. A→B→C lookahead must be able to reselect B when a viable B alternative exists.
5. Camera/VFX must resolve from existing Action Knowledge when available, with fallback only when no knowledge field exists.
6. Highlight quotas are soft; quality and factual provenance outrank quota completion.
7. No adapter may alter actor, weapon, event order, spatial state, physical result, damage, or ending semantics.
